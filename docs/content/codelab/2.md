Grow projects — called **pods** — are self-contained directories holding everything needed to render your site: content, templates, translations, static assets, and `podspec.yaml`.

The fastest way to start is by cloning the Grow repository and copying the built-in zero-Node starter pod in `examples/starter/`:

```bash
git clone https://github.com/grow/grow.git
cd grow/examples/starter
```

## Pod structure

A typical Grow pod has a small, predictable layout:

```text
/content/       # Content collections, blueprints (_blueprint.yaml), and documents.
/static/        # Static assets (CSS, JS, images, fonts).
/translations/  # PO message catalogs for localized strings.
/views/         # Jinja2 HTML templates.
/podspec.yaml   # Site-wide configuration (locales, static dirs, deployments).
```

Notice there is no application code or router script to maintain — `podspec.yaml` and each collection's `_blueprint.yaml` declare how content maps to URLs and templates. Changing a URL structure or adding a new locale is a one-line config edit.
